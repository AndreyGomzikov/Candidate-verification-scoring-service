# Объединённый отчёт `/status` — одно сообщение

## Новое поведение

- В личном чате администратор вводит **только** `/status`.
- Заголовок — одна строка: `SOLIDUS — история заявок Период: ДД.ММ.ГГГГ - ДД.ММ.ГГГГ`; границы определяются датами первой и последней сохранённой попытки вступления, без `(UTC)`. Для пустой базы выводится `Период: нет заявок`.
- При длине отчёта до **4096 UTF-16 единиц** бот отправляет **одно** текстовое сообщение: общая статистика и история всех записанных в PostgreSQL заявок вместе.
- Если полная история превышает лимит Telegram, бот отправляет **одно** сообщение с файлом `solidus-status-all.txt`, где без пропусков находятся и статистика, и вся история. Это не дополнительная команда `/status full`.
- Три ответа каждого кандидата всегда идут по порядку, отдельными строками. Для незавершённой анкеты выводится «Анкета не завершена. Баллы: не рассчитывались».
- Доступ — только из личного чата с ботом и только после успешной проверки актуальных прав владельца/администратора основной группы в Telegram. Если `ADMIN_USER_IDS` отсутствует в `.env`, специально добавлять его не нужно.
- Правила ИИ, обработка заявок и структура PostgreSQL **не менялись**.

## Изменённые файлы

- `app/handlers.py` — новая единая отправка `/status` с TXT-fallback.
- `app/main.py` — уточнён комментарий о длительной отправке; `block=False` сохранён.
- `tests/test_status_history.py` — тесты одного текста, одного документа, пустой истории, запрета нескольких параллельных отчётов.
- `README.md`, `STATUS_ONLY_DEPLOY_RU.md` — документация обновлена.

## Проверки

- `python -m compileall -q app tests` — успешно.
- Изолированная проверка на последних известных 12 заявках: **3445 UTF-16 единиц**, одно Telegram-сообщение; все 12 записей, статусы, ответы и оценки присутствуют.
- Сценарий 200 заявок: один TXT-документ, без потери истории; пустая база: одно текстовое сообщение.
- Полный `pytest` в рабочем окружении проверить дополнительно: здесь отсутствует `python-telegram-bot`, а внешняя установка пакетов недоступна.

## Рекомендованный порядок развёртывания

1. Сохранить резервные копии проекта и PostgreSQL по штатной процедуре.
2. Сравнить изменённые файлы с текущей веткой. Не копировать поверх более поздних исправлений без просмотра `git diff`.
3. В окружении с зависимостями выполнить: `python -m pytest -q tests/test_status_history.py`, затем `python -m pytest -q`.
4. Развернуть на тестовом окружении и отправить `/status` из личного чата владельца/администратора. Проверить один ответ, данные всех 12 записей и отсутствие сообщений `История 1/N`.
5. Проверить выгрузку при достаточно большой истории (один документ), запрет бывшему администратору и обычному пользователю.
6. При успешных проверках развернуть штатно (`docker compose up -d --build gatekeeper`) и проверить журналы ошибок.

**Важно:** количество сообщений ограничено одним, но для истории более 4096 единиц это будет **документ**, поскольку Telegram не позволяет отправить сколь угодно длинный текст одним сообщением.
